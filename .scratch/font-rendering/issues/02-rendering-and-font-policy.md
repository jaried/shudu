## Question

在真实渲染链、字体覆盖和平台能力查明后，采用哪条文字渲染路线？字体依赖由系统、安装前置条件还是随应用提供承担？明确中文、数字和界面符号的成功条件，以及字体缺失时用户可见的行为；由用户批准相应取舍。

## Answer

用户于 2026-10-12 确认完整路线：

1. Linux 与 Windows 沿用原生 Tk。校正 named font 的使用，并分别核验 Linux 的实际字体后端、Windows 的字体平滑与 DPI，按目标尺寸重绘文字。
2. 字体由系统提供。分别选择中文、数字与界面符号的可用字体组合，允许平台使用各自系统字体。
3. 首选字体缺失时，显示缺失的字体名称，使用系统回退字体继续运行，保持正常使用。呈现层负责字体选择、回退与可见提示。
4. 字符完整性覆盖中文、数字、英文与既有界面符号；清晰度、布局和既有交互继续按 S1-09 的正式 AC 验证。
5. 字体规则归呈现层。View 的绘制 Interface、Hint→View 依赖方向和 Tk 菜单资源生命周期沿用现行 ADR；Game、solver 与截图能力保持各自 owner。具体字体匹配与资源细节由后续工程设计确定。

原乱码发生在 Linux。具体页面、字符与复现画面由后续原型核验承接。Windows 独立解释器的隐藏探针已补齐字体和 DPI 事实，项目实际运行与高 DPI 观感尚未验证。
