# ADR-005 本地自动算法偏好与完成动画

## 状态

已接受 — 2026-10-06 更新

## 背景

桌面端新增两个跨层需求：

1. 自动解决算法的逐项勾选需要跨进程保留；
2. 行、列、宫正确完成后需要播放参考视频中的完成动画。

如果让 `Game` 直接访问配置文件，会把 IO 生命周期混入确定性状态机；如果让 `Game` 持有 Tk `after()` 动画，又会把展示时序混入领域状态。两者都会扩大 Interface，并降低测试 Locality。

## 决策

### 自动算法目录

`shudu/auto_techniques.py` 成为自动算法名称、顺序、显示标签和默认勾选的唯一生产真源。

`shudu_solver.py`、`Game` 和本地偏好模块只消费该目录，不再分别复制同一份配置元数据。

`UserSettings.auto_solve` 是自动求解总开关，`auto_techniques` 保留逐项算法选择。总开关默认开启，以兼容原有自动行为；关闭时保留勾选集合，全部自动求解入口均在 `Game.auto_solve_enabled()` 内返回，不创建 solver、不修改棋盘或候选状态。开启且有勾选算法时才执行 `ShuduSolver.solve_techniques_result(names)`。

`Game.set_auto_solve()` 和 `Game.set_auto_technique()` 只修改配置。启动、重开关卡、截图导入都继承总开关与算法选择；关闭总开关时“自动笔记”仍根据正式棋盘生成基础候选。Hint recommendation 固定使用全部逻辑算法；现有 `Game.notes` 按格提供当前候选状态。

### 本地偏好

`shudu/user_settings.py` 提供 `UserSettingsStore.load()` / `save()` 这一小 Interface，内部隐藏：

- Windows / macOS / Linux 用户配置路径；
- JSON 格式；
- 总开关与逐项勾选的联合保存，旧配置缺少总开关时按默认开启读取；
- 损坏配置回退；
- 算法名称校验；
- 同目录临时文件 + `os.replace()` 原子写入。

GUI 入口拥有 store 生命周期。`Game`、solver 和 View 不依赖文件 IO。

### 完成事件

`Game.completed_units()` 只返回当前已经正确完成的行、列、宫，是确定性的只读状态查询。

`SudokuWindow` 在一次游戏动作前后比较该结果，只把“本次新完成”的区域交给 View。

`SudokuView.animate_completed_units()` 拥有 Tk 定时器、帧状态、颜色和扫光顺序。动画不写回 Game。

## 结果

依赖方向为：

```text
auto_techniques ─→ solver / Game
        │
        └────────→ user_settings ─→ GUI

Game.completed_units() ─→ GUI ─→ SudokuView.animate_completed_units()
```

因此：

- 算法配置元数据保持单一真源；
- 自动执行由总开关与勾选集合共同决定；Hint recommendation 沿用独立的全算法和现有笔记输入；
- 持久化 IO 集中在一个深 Module；
- Game 仍可在无窗口、无文件系统替身的情况下确定性测试；
- View 动画可以独立修改而不影响求解或撤回语义；
- 没有为了单一文件存储实现引入额外 Port/Adapter 层。

## 验证

架构测试锁定：

- `user_settings` 不依赖 Game、View、Tkinter 或 solver 入口；
- Game/View 不依赖 `user_settings`；
- 自动算法目录不在 Game/solver 中重复定义；
- 动画定时器只存在于 View；
- 根目录继续只保留可执行入口。
