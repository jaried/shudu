# ADR-005: 自动偏好与设置菜单的能力执行面

## 状态与来源

已接受 — 2026-10-06修订。用户已确认完整联合方案并授权发布；批准见[发布批准](../01_sprint记录/sprint01/00-联合方案决策/2026-10-06/发布批准记录.md)。本ADR描述已批准目标，代码迁移及运行验证由承接Issue后续执行。共同规格见[联合方案](../01_sprint记录/sprint01/00-联合方案决策/2026-10-06/联合方案决策.md)。

## 背景

自动目录、本地偏好与完成动画已有明确owner。设置菜单近期支持持续选择，当前通过tk.Menu中间表示反查变量/command再建立ttk界面，配置回调也进入完成扫描和整盘绘制路径。优化应隐藏这些实现知识，同时使配置操作只运行必要能力。

## 决策

1. `shudu/auto_techniques.py`继续为名称、顺序、标签和默认勾选真源；十种技巧和Hidden Triple默认关闭保持。
2. UserSettings.auto_solve默认开启，各项选择独立；Game.set_auto_solve/set_auto_technique只修改配置和原消息。Game.auto_solve_enabled先完成总开关/选择/状态/错误gate，再请求一次solve_auto完整结果；禁用路径零solver。
3. Game只应用同轮完整自动结果，保持撤回、累计删除和完成判定；Hint使用全算法与现有notes，两个能力分别执行。
4. `shudu/settings_menu/`是设置菜单deep Module，公开入口`__init__.py`；model、popup、position为internal。它只接收当前设置、已有关卡元数据和业务动作回调。
5. 菜单直接创建当前ttk条目，一次勾选只更新对应行；窗口接收具体设置或菜单命令。开关保持弹层，其他命令先关闭后执行。当前Tk是唯一实际Adapter。
6. 自动总开关/技法调用Game setter、更新既有message项并调用原_persist_auto_settings；已有store时保存完整自动偏好一次，无store时save为0。View.update_message只修改既有项text，无该项时结束；完成扫描、整盘重绘、动画、候选投影和solver均为0。auto_clean仅赋值Game.auto_clean与菜单标记，其message更新、store访问和save均为0。
7. GUI继续拥有UserSettingsStore的load/save生命周期，持久化字段沿用auto_solve与auto_techniques；store内部沿用跨平台路径、JSON兼容、名称校验、同目录临时写入和os.replace。自动偏好保存失败明确提示、内存配置保留；下次自动总开关/技法选择再保存。
8. 启动/重开/截图导入继承自动配置；截图初始notes沿用ADR-004；关闭自动求解的“自动笔记”仍生成基础候选。
9. Game.completed_units是确定性查询；只有实际游戏操作前后由GUI比较新完成单位，动画的after和颜色状态归View。
10. 菜单的悬停、连续鼠标/键盘选择、Esc/外部点击/失焦关闭、显示器工作区和grab释放保持；close效果一次且重复调用结束。提示任意Canvas点击仍关闭提示；完成态仍可打开设置，完成文案、只读按钮和动画进度保持。直接Hint设置回调增加控件identity保持的资源保证，依据见[grilling事实](../01_sprint记录/sprint01/00-联合方案决策/2026-10-06/证据/grilling-业务事实核验.md)。

## 取舍与影响

用具体设置数据与动作代替Tcl字符串反查，菜单知识集中；窗口仍负责持久化与游戏命令，因此Game、View和solver保持与IO独立。增量消息更新依据当前控制启用状态不依赖自动偏好的事实，保留棋盘和Hint文本控件。

资源与交互继续由实际Tk事件驱动；本地save采用当前同步一次尝试，避免改变即时保存与错误可见行为。新窗口动作闭集沿当前产品需求，不引入通用渲染扩展体系。

## 验证与生效

真实Windows Tk事件/生命周期、即时保存及失败、配置零计算面、Hint控件保持、多显示器范围和完成动画均需真实证据。当前两次完整测试出现Tk setup错误，保留待定位事实，隔离测试通过不替代全量门禁。本修订已获明确发布批准，完成PublicIoGovernance校验及实际文本readback；实施与required运行证据由承接Issue后续取得。
