# ADR-002 共享规则内核与求解器公共接口

## 状态

已接受 — 2026-09-14 更新

## 背景

GUI、Game、提示和求解器都需要共享数独拓扑与候选规则。提示界面还需要知道一步推理的依据格和观察区域。如果上层通过候选快照重新识别 Naked Pair、Pointing、X-Wing 等模式，就会形成第二套算法知识并破坏 Locality。

仓库根目录同时堆放入口和内部实现，也使可执行 Interface 与内部 Implementation 难以区分。

## 决策

1. `shudu/sudoku_rules.py` 是纯领域规则 Module，提供拓扑、坐标类型和基础候选；不依赖 GUI、Game 或 solver 状态。
2. `shudu/sudoku_logic.py` 拥有候选状态、技巧执行和每一步算法证据。
3. 根目录 `shudu_solver.py` 是项目级 solver seam，公开 `next_step()`；返回的 `LogicStep` 一次包含 `placements`、`eliminations`、`sources`、`units` 和候选快照。
4. `shudu/sudoku_hints.py` 只消费 `LogicStep`，不得重新识别高级数独模式，也不得调用 solver 私有 step 方法。
5. `shudu/sudoku_hint_view.py` 只消费 `Hint`，复用 `SudokuView.draw_header()` 与 `draw_grid_lines()` 两个公开绘制 Interface，不跨 Module 调用私有方法。
6. `Game.notes` 与算法候选严格分离；用户笔记不是 solver 推理前提。
7. 非入口生产实现统一放入 `shudu/` 包；仓库根目录只保留可执行入口。
8. 上述依赖方向与目录约束由 `tests/test_architecture.py` 自动检查。

## 影响

- 高级算法模式只有一个生产真源：真正执行算法的 solver。
- Hint 文案与视觉效果可修改，而不需要复制或修改算法判定。
- GUI 不接触位掩码、Numba finder 或 OCR 阈值。
- 根目录直接表达启动入口，内部知识集中在包目录。
- 现有 `python sudoku_gui.py`、`python shudu_solver.py` 等启动方式保持不变。

## 不采用

- 不为每种技巧建立 Strategy class；当前没有第二种技巧实现需要该 seam。
- 不建立 View Adapter 注册表；当前只有 Tk Canvas 一个真实 Adapter。
- 不让 Hint 根据 `candidates` 反向重建算法来源；这会重新制造被本 ADR 消除的重复知识。
