# ADR-002 共享规则内核与求解器公共接口

## 状态

已接受 — 2026-09-13

## 背景

GUI、Game、提示适配和旧逻辑求解器都需要理解行、列、宫、peer 与候选。继续让上层直接从 `logical_solver.py` 导入 helper，会把一个实现文件变成事实上的公共领域 API；提示层直接调用 `_apply_next_step()` 还会让私有实现细节变成跨层契约。

## 决策

1. `sudoku_rules.py` 成为纯领域规则内核，提供拓扑、坐标类型和基础候选计算；它不依赖 GUI、Game 或求解器状态。
2. `logical_solver.py` 保留既有技巧实现，不承担新的项目级公共 API。
3. `ShuduSolver` 是 shudu 的项目级 solver seam，负责技巧优先级并暴露 `next_step()`。
4. `sudoku_hints.py` 只消费 `LogicStep` 和 `sudoku_rules`，不得直接调用 legacy solver 私有方法。
5. `Game.notes` 与算法候选严格分离；一键自动笔记只调用纯规则内核。
6. 依赖方向用 `tests/test_architecture.py` 自动检查。

## 影响

- 行、列、宫与候选的业务定义只有一个生产真源。
- GUI 提示可以替换 solver 实现而不改展示协议。
- 旧 solver 可继续独立运行，降低一次性大重构风险。
- 新抽象只覆盖已有的真实重复点，没有引入策略框架、容器或事件总线。

## 延后事项

`logical_solver.py` 仍是较大的算法实现文件。当前各技巧高度共享 `board/cands` 状态，按技巧拆文件只会把内聚代码拆散。只有出现第二种算法状态模型或频繁跨技巧回归时，才重新评估该拆分。
