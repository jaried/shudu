# ADR-004 截图输入深模块

## 状态

已接受 — 2026-09-14

## 背景

`shudu_gui.py` 需要支持把一个指定的数独游戏截图直接作为输入，恢复正式大数字和候选小数字后进入游戏；除了启动参数，还需要在已经运行的 GUI 中反复选择新的截图文件生成新局。

这个需求同时包含棋盘定位、图像二值化、正式数字识别、候选笔记解析、文件 IO 与错误处理。如果把这些细节放进 GUI，会让窗口层同时知道 OpenCV、OCR 阈值和数独截图版面规则，形成浅模块并扩大测试面。

此外，正式大数字和候选小数字不能只靠“识别出了什么字符”区分：数字没有大小写。截图中的语义差异来自版面：正式数字尺寸大且居中；候选数字尺寸小，并位于单格内部固定的 3×3 候选位置。

## 决策

新增 `sudoku_screenshot.py`，作为截图输入的深模块。

它只暴露一个主要入口：

```python
load_screenshot_game(path) -> ScreenshotGameInput
```

调用方只需要提供文件路径，并接收：

- `Puzzle`：只包含正式大数字；
- `notes`：只包含候选小数字。

模块内部隐藏：

- 截图文件读取；
- 9×9 棋盘定位和归一化；
- 单格连通域分析；
- 正式大数字与候选小数字的尺寸/位置分类；
- 正式数字的模板识别；
- 小数字按 3×3 候选位置直接恢复为 1–9；
- 中文路径读取和失败原因。

`shudu_gui.py` 只调用这个入口，不访问 OpenCV、阈值、模板或单格识别细节。

不新增抽象基类、Adapter 注册表或 OCR Provider seam。目前只有一个真实截图实现；按照 codebase-design 的原则，一个实现不足以证明需要额外可替换 seam。

## 正式大数字与候选小数字规则

每格先做连通域分析：

1. 高度、面积达到正式数字阈值且位于格子中心区域的主体，判定为正式大数字，再进行 1–9 字形识别；
2. 未出现正式大数字时，只接受尺寸较小的连通域作为候选；
3. 候选数字不依赖 OCR 字形，而按连通域中心落入单格内部哪一个 3×3 槽位，直接映射为 1–9；
4. 一个格子一旦识别为正式大数字，该格不再恢复候选笔记。

这样“正式数字 / 笔记”分类依赖稳定的版面语义，而不是把字体大小误当成两个字符类别。

## GUI 输入契约

命令行可直接指定截图：

```bash
python sudoku_gui.py path/to/screenshot.png
```

运行中的 GUI 也提供“从截图导入…”菜单项。用户可以重复选择新的截图文件，每次都通过同一个公开加载接口创建新的 `Game`，不需要重启程序。

GUI 导入流程：

1. GUI 只负责让用户选择文件；
2. 调用 `load_screenshot_game(path)` 恢复题面和笔记；
3. 用题面创建 `Game`；
4. 把截图候选笔记恢复到 `Game.notes`；
5. 保留当前“自动简单算法”和“正确填数后清理笔记”偏好；
6. 统一替换窗口当前 `Game`，重新绑定命令并重绘；
7. 文件取消时保持当前游戏不变；识别失败时显示明确错误并保持当前游戏不变。

截图刚导入时保留截图中的笔记，不立即用自动简单算法覆盖它们。后续玩家正确落子或显式触发自动逻辑后，仍按现有 `Game` 规则运行。

如果当前游戏已经有进度，导入新截图与切换内置关卡共用同一个“是否放弃当前进度”确认逻辑，避免两个入口产生不同生命周期规则。

## 影响

### 正面

- GUI 接口保持很小，只知道“路径 → 游戏输入”；
- 图像识别复杂度集中在单一模块，符合 Depth / Leverage / Locality；
- 正式大数字与候选小数字有明确、可测试的语义边界；
- 同一个 GUI 会话可以反复导入不同截图；
- 不依赖外部 OCR 服务、网络或模型文件；
- OpenCV 细节不会泄漏到 Game、solver 或 view。

### 代价

- 当前正式数字识别使用本地模板库，针对清晰的数独 UI 截图优化；极端字体或严重压缩截图可能低置信度失败；
- 当前棋盘定位面向屏幕截图，不处理明显透视畸变的相机照片；
- 候选数字需要遵循常见的单格 3×3 候选位置布局。

失败时明确抛出 `ValueError`，不静默猜测错误题面。

## 验证

`tests/test_sudoku_screenshot.py` 使用合成截图验证：

- 9×9 棋盘定位；
- 正式大数字识别；
- 候选小数字按 3×3 位置恢复；
- 大数字不会被当成候选；
- 中文文件路径；
- 深色高亮格中的正式数字；
- GUI 启动层能直接恢复题面和笔记。

`tests/test_screenshot_import_menu.py` 验证：

- GUI 菜单存在“从截图导入…”入口；
- 导入后保持现有游戏偏好；
- 同一窗口可以连续导入多个文件；
- 导入失败不会破坏当前游戏。

`tests/test_architecture.py` 锁定 `sudoku_screenshot.py` 不依赖 GUI、Game、Hint 或 solver，防止识别实现向上层泄漏。
