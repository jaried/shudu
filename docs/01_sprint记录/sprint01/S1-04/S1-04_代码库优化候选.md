## Depth、locality 与 deletion test

菜单 Module 隐藏条目构造、当前勾选显示、悬停子菜单、定位和 grab 释放，公开 interface 只承载实际业务需要，形成 depth。修改菜单交互可集中在 Module，形成 locality；窗口和真实 Tk 测试跨越同一 seam，保留 leverage。Tk/ttk 是当前唯一真实 adapter，现有 interface 足以处理产品需求。

删除菜单 Module 会把呈现、定位和生命周期知识重新分散到窗口，复杂度不会消失。删除动作模型会让调用方重新理解 widget 或 Tcl 状态。当前分工有实际职责，继续细分成通用渲染体系没有真实第二个 adapter 或业务需求支撑。

## 实际执行面

| 用户动作 | 允许发生的当前工作 |
| --- | --- |
| 自动总开关或技法选择 | 更新对应菜单行；调用 Game setter；修改已有消息项；有 store 时同步保存完整自动偏好一次，无 store 时结束。 |
| 自动清理选择 | 更新对应菜单行与 `Game.auto_clean`。message 更新、store 访问与 save 均为 0。 |
| 真正游戏操作 | 沿原窗口动作路径比较新增完成单位并播放动画。 |
| Hint / 完成画面的直接设置回调 | 没有普通消息项时增量更新结束；保留原 Hint 结果、文本控件和完成画面。 |

设置动作路径没有求解器构造、finder、候选投影、完成单位扫描、整盘 draw 或动画入口。Hint 的普通 Canvas 点击仍关闭提示，完成态仍可打开设置；本次能力收紧没有扩大当前动作可达范围。完成动画的定时器和颜色继续由 View 拥有。
