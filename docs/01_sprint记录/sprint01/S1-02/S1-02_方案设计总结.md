## 三图与字段闭合摘要

业务流程从 Hint 请求进入 Game/Hint 错误门禁，经过单步 capability 的 notes 投影、项目首步和执行前证据，返回 `LogicStep` 或 `None`，再由 Hint/View 展示。数据流程由 Game 生产 board/notes，Module 生产 `_masks`、动作、消息、来源、单位、候选快照和 `technique_name`，Hint 生产中文和视觉适配字段；每个字段拥有单一 producer。逻辑流程保持同步、首命中停止、成功/无步骤/异常统一清理动态采集。

冻结的字段责任是：`_engine.py` 生产 message、动作和命中身份；`_evidence.py` 生产 Hidden Single 来源/单位；`_project.py` 绑定项目优先级和一步装配；`_results.py` 冻结步骤字段；`_single.py` 生产 notes 投影和公共能力返回；`sudoku_hints.py` 生产标题、文案和视觉 regions。Hint 不读取私有 finder、日志编号或自动偏好。

## 测试与执行面

测试使用版本化的固定最小 fixture：默认 `Game()` 盘面、关卡119、截图 notes、关卡119部分 notes、`SECOND_PUZZLE` 和全零盘面。设计保留十种技巧、关卡119 Hidden Pair 删除7、截图 Hidden Triple 六项删除、输入只读、错误零求解、无步骤和自动偏好独立的行为要求。

实施顺序冻结为 RED → GREEN → regression：先在公开 Interface 固定新合同，再完成最小实现和 Hint 接线，最后运行 required pytest、固定行为回归和执行面探针。required 命令为：

```text
.venv/Scripts/python.exe -B -m pytest -q tests/test_sudoku_hints.py tests/test_shudu_solver.py tests/test_njit_core.py tests/test_architecture.py
```

当前迁移前 focused 基线为 `63 passed`；联合方案保存的完整基线为 `237 passed、1 个 Tk fixture setup error`。这些记录保持真实边界，设计阶段未宣称目标实现通过。实施阶段必须保存实际 RED、GREEN、回归、执行面和 HOST readiness/readback。

调用规模预算冻结为：有效 Hint 一次 `next_hint_step`、一次 solver、一次 `next_step`；首命中停止；notes 只遍历现有条目；Hidden Single 来源计算一次；自动和 legacy 新增单步采集与完整步骤快照为 0；产品 IO、子进程和远端调用为 0。

首评整改把联合机器基线的实际字段纳入 I01 证据闭环。基线文件为
`docs/01_sprint记录/sprint01/00-联合方案决策/2026-10-06/证据/shudu-execution-surface-baseline-20261006.json`，探针字段为：

| 维度 | 实际字段 | 已读回的固定场景上限 |
| --- | --- | --- |
| board 扫描/mask 构造 | `masks_from_board`、`array_shapes` | 单步场景 `masks_from_board=1`，形状 `[[9,9]]`；wrong 场景为空数组、调用为 0 |
| candidate 扫描 | `capture_candidates` | auto 全十为 10；auto Hidden Triple-only、单步 Hint 和 Hidden Single 为 1；wrong 为 0 |
| candidate 集合/转换 | `candidate_sets` | auto 全十为 10、auto Hidden Triple-only 为 1、无 notes 无步骤为 2、Hidden Triple/Hidden Single 为 3、wrong 为 0 |
| mask propagation | `apply_placement` | Hidden Single 为 1；其余已采集固定场景未出现，按 0 |
| 步骤/来源 | `next_step`、`base_hidden_single_evidence`、`project_hidden_single_evidence`、`find_*` | Hidden Single 的步骤和两级来源均为 1；其他 finder 计数按同场景 JSON `calls` |

成功、无步骤、wrong、异常和 Hidden Single 均要求由同一 `record()` 字段集形成证据。联合 JSON 已覆盖成功、无步骤、wrong 和 Hidden Single；异常场景尚无 JSON 行，HOST 在 implementation readiness 前使用既有最小固定 fixture 和相同 seam 补采 `calls`/`array_shapes`，再写入 I01 readback。设计阶段保留真实未知，不预填异常计数。
