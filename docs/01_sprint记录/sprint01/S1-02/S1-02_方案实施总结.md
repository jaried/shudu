# S1-02 方案实施总结

## 1. 实施结论

S1-02 已按冻结的 `S1-02-design-v2` 完成 I01 单步事实能力。公开入口
`shudu.logic_solver.next_hint_step(board, notes)` 负责一次 solver、一次
`next_step`、现有 notes 投影和完整 `LogicStep`；`sudoku_hints.py` 只保留
中文标题、文案和视觉区域适配。`LogicStep` 原六个位置参数保持兼容，新增
`technique_name` 为尾部可选字段。

本次实现提交前的实施基线为 `c4bfd4655ab15e2797839d522974ee1985ef193a`；
提交 SHA、父提交和精确路径由 AutoCommit/readback 记录。当前成果具备独立
Implementation Reviewer 定向复核条件。

## 2. 已完成的 Implementation Item

### I01：单步事实 capability

- `_single.py` 建立唯一单步 capability：构造一次 `ShuduSolver`，取得一次
  候选快照，按现有 notes 做候选投影，再调用一次 `solver.next_step()`。
- `_project.py` 将单步上下文绑定为 message、placements、eliminations、
  sources、units、candidates 和 `technique_name`，成功、无步骤、异常出口
  均执行动态上下文清理。
- `_engine.py` 只在单步首命中记录技巧身份和 Hidden Single 命中 unit；
  `_evidence.py` 负责 Hidden Single 来源/单位一次计算，保持
  box → row → col 的既有优先级。
- `logic_solver.next_hint_step` 是按需加载的薄 wrapper；`_project.py` 只在
  Hidden Single 实际装配时加载 `_evidence`，legacy/auto 导入不预热
  `_single` 或 `_evidence`。
- `_results.py` 通过尾部可选 `technique_name` 固定新旧字段语义；旧自动和
  legacy 求解路径继续使用原结果和执行面。
- `sudoku_hints.py` 通过公开 capability 取得步骤，保留既有十技巧、关卡119、
  截图 notes、错误提示和视觉语义。
- `tests/test_s1_02_single.py` 覆盖默认 Game Hidden Single、关卡119截图
  Hidden Triple 六项删除、空盘无步骤、错误输入只读、单次 solver/step、
  六字段兼容和异常后清理恢复；`tests/test_architecture.py` 固定入口与
  adapter 边界。

## 3. 设计符合性与执行面

实施代码按冻结 Module → Interface → Seam → Adapter 闭合：

| 层 | 实际 owner | 实施事实 |
| --- | --- | --- |
| Module | `shudu/logic_solver/` | 求解、候选、步骤动作和事实字段集中在既有 solver module |
| Interface | `logic_solver.next_hint_step` | caller 只传 `board`、`notes`，取得 `LogicStep` 或 `None` |
| Seam | `_single.py`、`_project.py`、`_evidence.py` | notes 投影、单步装配、Hidden Single 来源各一处 |
| Adapter | `sudoku_hints.py` | 只转换标题、文案、cells 和视觉 regions |

单步路径保持 board/notes 输入只读，首命中停止，动态字段通过 `finally`
清理。自动路径和 legacy 路径不产生新的单步快照或 `LogicStep`。生产代码
没有新增 IO、子进程或 remote 调用；探针只在证据脚本中观察既有函数。
