# S1-03 方案设计评审整改记录

## 整改范围

本记录消费首评报告 `S1-03-design-review-v1` 的四个 blocker，仅补足批准方案中的可执行行为和防回归证据。整改没有新增 capability、Module、Interface、owner、依赖、测试策略或产品范围。

## REV-001：完整 envelope 比较与 notes-only 应用

- 处理：删除“finder 无进展即 Game 无状态变化”的绝对表述，明确固定点无进展后仍生成最终 notes 和完整 envelope。
- 冻结语义：Game 只有在 `board`、`notes`、累计 `eliminations` 三项全部相同才 no-op。`placements=0`、`eliminations=()` 但 notes 改变时仍接管 notes；`remember=true` 保存一次，消息、`active_digit`、完成判断按原顺序执行，公开返回值为 `0`。
- 证据：方案设计第 2.1、2.2、3.1、7.1；UT-012 完整 envelope 相同 no-op；UT-013 notes-only application；E2E-004；I03/I04/I05 required checks。

## REV-002：metadata 执行面计数

- 处理：把兼容 metadata 路径的稳定计数写入 Interface、迁移表、测试和执行面 probe。
- 冻结计数：`final_notes=0`、`LogicStep=0`、`capture_candidates=0`；metadata path 的 `candidate_sets=0`。自动生产结果路径单独允许最终 `candidate_sets=1`，并保持 `final_notes=1`、`LogicStep=0`、`capture_candidates=0`。
- 证据：方案设计第 3.3、6.1、9、10.2、10.3；UT-010；IT-005；metadata probe；I02/I04/I05 required checks。

## REV-003：Single 落子与 peer propagation fixture

- 处理：新增 DATA-007 固定 `int64` before/after mask，以及 UT-014、IT-006 的具体删除集合。
- 冻结 fixture：before 中 R1C1=`{1}`、R1C2=`{1,2}`、R1C4=`{1,5}`、R2C1=`{1,3}`、R2C2=`{1,4}`、R4C1=`{1,6}`、非 peer R4C4=`{1,7}`；after 将 R1C1 置空并移除 1 的 peer 位。`mask_diff` 按 row/col/digit 返回 `(0,0,1)`、`(0,1,1)`、`(0,3,1)`、`(1,0,1)`、`(1,1,1)`、`(3,0,1)`，不返回 `(3,3,1)`。
- 证据：方案设计 DATA-007、UT-014、IT-006、I02/I04/I05 required checks；同时保留既有 Pair/Triple/Pointing fixture 和 nopython 检查。

## REV-004：异常完整 Game 快照恢复

- 处理：新增 DATA-008、UT-015、IT-007、E2E-005，并把异常恢复字段写入 producer/consumer 和 Implementation Items。
- 冻结快照字段：`board`、`notes`、`history`、`simple_eliminations`、`status`、`active_digit`、`message`、`completed_units()`。
- 注入点：solver 构造、selected finder、`mask_diff`、最终 `algorithm_candidates`/notes 组装。每个异常都必须在 envelope 交付前传播，所有快照字段逐项保持调用前值。
- 证据：方案设计第 2.2、7.2、10.2、10.3、I01/I03/I04/I05 required checks。
