## Depth、locality 与 deletion test

完整自动结果使 Game 从读取 solver 和 metadata 两条渠道收敛到一个小 interface。Module 隐藏候选恢复、技巧固定点、真实删除与最终笔记产生，形成 depth；Game 保留游戏状态应用，求解知识集中，形成 locality。产品与结果回归跨越同一 seam，获得 leverage。

删除自动完整结果会让 Game 再次理解可变 solver、候选投影和结果同步时序。删除差分内部实现会把掩码与删除顺序知识混回项目编排。复杂度会转移，收益不成立。当前 root / legacy adapter 保留真实兼容用途；当前自动能力没有第二个算法实现 adapter，无需扩大通用切换层。

`AutoSolveResult` 的 board 和 notes 转交 Game 单一所有权；现有测试验证输入和跨次结果独立。继续增加不可变深复制会改变已批准结果所有权与执行面，当前没有业务依据。

## 实际执行面

- 总开关关闭、选择为空、状态非 playing 或存在错误数字时，Game 在能力调用前返回。
- 自动只扫描显式勾选集合到固定点；沿正式棋盘和已证明删除工作，不读取手工 notes。
- 失败技巧之间不生成 Python 候选网格或单步快照；首个成功技巧后才进入数值差分，生产最终 notes 仅生成一次。
- 兼容元数据路径不生成最终 notes 或 LogicStep；单步 Hint 继续按现有 notes 请求一次步骤，不加载自动或差分能力。
- board、notes 与删除事实在能力成功返回后应用；异常出口保持 Game 原状态，无变化结果保持原历史、消息与完成状态。
- Numba finder、9×9 int64 mask、技巧顺序和本地缓存保持既有范围。此扫描不以结构变化推断耗时加速比例，也未增加产品 IO、子进程或远端调用。
