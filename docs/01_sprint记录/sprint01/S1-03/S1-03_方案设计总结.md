## 三图与闭合摘要

业务流程从 Game gate 进入一次自动 capability，沿选中算法集合运行到固定点，组装一次 envelope 后由 Game 接管；gate、无进展和异常出口均保持原状态。数据流程由正式 board、勾选集合和已证明删除进入 solver mask，经 Numba finder 和一次 mask 差分得到删除，再由最终 mask 生成 notes，回到 Game 的唯一状态 owner。控制流程明确了 gate、solver、pass、差分、固定点、结果应用、history 和 undo 的状态变化。

## 执行面与兼容

每个自动 pass 至多一份 9×9 mask copy；失败 finder 不创建 Python 候选集合；成功后 `_diff.py` 使用 `@njit(cache=True)` 按行/列/数字差分，包括落子传播。最终 notes 只在生产自动结果路径构造一次。metadata 兼容方法继续返回 `SimpleSolveResult` 或数量，不生成 final notes、完整 `LogicStep` 或单步采集。Game 不持有可变 solver，结果 board/notes 在一次 transfer 后由 Game 拥有。
