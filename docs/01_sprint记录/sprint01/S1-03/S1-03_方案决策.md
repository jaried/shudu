# S1-03 方案决策：自动结果能力

正式Issue：S1-03。共同规格：[联合方案](../00-联合方案决策/2026-10-06/联合方案决策.md)；原始需求：[S1-03_原始需求.md](S1-03_原始需求.md)。批准依据：[发布批准](../00-联合方案决策/2026-10-06/发布批准记录.md)。

## 问题、目标与独立交付

当前Game要同时读取SimpleSolveResult和可变solver，再自行构造最终notes；自动扫描每个失败技巧还生成整盘Python候选快照。本票让已选算法执行产出一次完整结果，Game只应用该结果，保留固定点、累计删除、撤回与自动门禁，计算面减少。

## 独立方案切片

Module为逻辑求解；Interface为`solve_auto(board, names, proven_eliminations) -> AutoSolveResult`；Seam位于Game的既有自动执行入口；Game作为结果消费者保留其游戏状态职责。

`_auto.py`构造一次项目solver、恢复proven_eliminations、仅执行names到固定点，转交最终board/notes/数量/本轮删除。结果采用联合规格4.1的唯一所有权envelope；不多做不可变棋盘冻结再回转，结果与输入、另一轮结果互不别名。

`_project.py`的自动一步扫描改为每轮一次9×9 mask snapshot，在首个成功技巧后使用`_diff.py`的njit整数差分获取真实删除；不再为失败技巧转换Python set网格。删除含落子传播，维持行列数字顺序与固定点首次出现去重语义。未命中时返回无进展；算法顺序和选择范围保持。

Game在原门禁之后一次请求能力；`_apply_auto_result`只消费完整结果，沿原代码应用记忆、累计删除、active_digit、消息及完成状态；`_solver_notes`及solver/result双通道被新行为证据替代。已有metadata兼容方法继续返回原SimpleSolveResult/数量，final notes组装不进入这些调用；生产自动调用不进入单步采集。

## owner_surface 与函数级允许范围

生产对象：`_auto.py`、`_diff.py`；`_project.py`的自动扫描/solve结果/候选删除差分函数；`_results.py`中AutoSolveResult；公共入口的自动能力；Game.auto_solve_enabled、_apply_auto_result、_solver_notes及所需导入。测试对象：自动、选择、njit差分、结果别名、Game应用/撤回、对应architecture检查。

S1-02修改单步和证据函数，不改变本票自动函数；两个Item只共享S1-01已经稳定的engine接口。public入口、结果载体和测试文件按不同成员协调；不因同文件设置串行边。

## 行为、边界与失败

总开关关闭、勾选为空、非playing或wrong盘面在Game返回0，capability调用和solver构造为0。自动只读正式棋盘与已证明删除，不读手工notes。配置勾选本身保持盘面；显式自动笔记关闭自动求解时沿用基础规则。names校验沿用ValueError。内部失败不返回可应用的半个结果，Game保持调用前状态；输入独立复制与现有构造一致。成功后Game按原remember语义至多记忆一次；相同最终结果保持原无变化返回。

## 验收与 required 测试

- [ ] 完整结果独立于输入与其他执行结果；Game不持有可变solver；board接管不额外复制整盘。
- [ ] Game门禁零调用、错误/无进展/撤回/基础自动笔记场景真实通过。
- [ ] metadata兼容调用的最终notes、完整LogicStep与单步采集次数为0；每轮mask copy≤1。
- [ ] 差分helper有真实nopython签名，输出与旧真实删除保障一致，finder不增加。
