# S1-01 方案设计评审整改记录

## Finding 绑定

本记录承接首评报告 [S1-01_方案设计评审报告.md](S1-01_方案设计评审报告.md) 的 `S1-01-REV-001`，评审报告版本为 `S1-01-design-review-v1`，绑定 `Sprint01|S1-01|solution-design`。首评结论是 `changes_required`，唯一 blocker 是 legacy `LogicSolver` 的 Module → Interface → Seam → Adapter → 文件布局未冻结唯一物理 owner。

## 真实代码事实

当前 [logical_solver.py](../../../../logical_solver.py) 的 `LogicSolver` 定义位于第 115 行，形状为 `class LogicSolver(NumbaLogicSolver)`，第 118 行类体为 `pass`。当前文件同时拥有 parse、print、unit helpers、legacy CLI 和名称导出；`NumbaLogicSolver` 来自 `shudu.sudoku_logic`。该类没有独立算法实现，legacy 的 Naked Single → Hidden Single 行为来自其基类的 `_non_marking_techniques()` 和既有 solver 方法。

当前 [tests/test_njit_core.py](../../../../tests/test_njit_core.py) 已验证 `issubclass(LogicSolver, NumbaLogicSolver)` 及 legacy/project 两种优先级；[tests/test_logical_solver.py](../../../../tests/test_logical_solver.py) 覆盖 legacy 求解、fallback、日志和错误出口。这些事实要求根名称、模块 identity、构造参数、继承关系和 pass 类体保持为兼容 Adapter 合同。

## 最小整改

整改只冻结 owner 和文档，不修改生产代码：

1. `logical_solver.py` 继续物理拥有 `LogicSolver` 类体；它是根 legacy Adapter 的名称/类 identity 兼容层，保留 pass 类体、构造参数、helpers、CLI 和公开导出。
2. `NumbaLogicSolver` 的实现、旧 Naked Single → Hidden Single 执行行为、finder、候选、日志和完整 solve fallback 归 `shudu/logic_solver/_engine.py`；根 `LogicSolver` 仅通过公开入口取得基类。
3. `ShuduSolver` 的项目实现归 `_project.py`；`_results.py` 归属结果类型和快照构造。
4. `single`、`evidence`、`auto`、`diff` 是 S1-02/S1-03 在真实 capability 需要时新增的 internal 位置；S1-01 保持本票已冻结的最小目录和职责。
5. I02 只承担 `_engine`、`_project`、结果和导入迁移；I03 明确承担根 `LogicSolver` identity、基类导入、caller aliases 和兼容 smoke；旧 legacy 测试同步绑定这些检查。
