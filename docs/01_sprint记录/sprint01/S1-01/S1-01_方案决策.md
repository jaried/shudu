# S1-01 方案决策：求解模块目录迁移

正式Issue：S1-01。共同规格：[联合方案](../00-联合方案决策/2026-10-06/联合方案决策.md)；原始需求：[S1-01_原始需求.md](S1-01_原始需求.md)。批准依据：[发布批准](../00-联合方案决策/2026-10-06/发布批准记录.md)。

## 问题、目标与独立交付

当前求解实现跨 `sudoku_logic.py`、根 `shudu_solver.py` 和 `sudoku_step.py`，公共调用与内部实现位置混合。本票把同一求解 Module 迁入单一目录，根入口继续可执行且现有玩家行为相同；本票单独完成即可验证，不等待后续能力优化。

## 独立方案切片

Module 为逻辑求解；Interface 为当前真实公开类/结果及方法；Seam 为项目、legacy、Hint和Game入口；Adapter 为保留的根CLI入口。实现迁入 `shudu/logic_solver/`，公开入口为 `__init__.py`，旧Numba实现位于`_engine.py`，项目求解器位于`_project.py`，不可变步骤及原SimpleSolveResult位于`_results.py`。原算法、候选状态、优先级、日志、错误与fallback代码语义原样保持。

根 `shudu_solver.py` 保留现有公开类/目录常量/CLI的导入行为，业务实现转出来自公共入口；`logical_solver.py` 保留helpers、LogicSolver名字与旧优先级，基类从新入口取得。内部公共入口不导入根CLI helpers；project内部本来只供CLI使用的parse/print移留根入口。Hint/Game只迁移结果类型引用，不在本票改变业务调用。

旧 `shudu/sudoku_logic.py` 与 `shudu/sudoku_step.py` 的所有直接引用和测试别名迁移后移除。迁移当天行为测试同步迁移，根私有字段文字断言改为公共一步产物断言，保持原“solver直接提供证据”保障。根目录仍恰好五个可执行文件。

本票不新增finder、候选投影、快照或运行实例；冷导入只定义必要类与类型，调用计数与原实现相等或减少。依赖面从root/legacy helper知识收敛为一个Module公开入口。

## owner_surface 与函数级允许范围

生产对象：`shudu.logic_solver`公开入口/三份迁移internal；根项目/legacy入口的导入和CLI职责；Game、Hint的结果类型导入。测试对象：conftest中两项迁移别名、njit基类引用、architecture目录/依赖/公共结果检查；保留原行为测试数据。后续S1-02的`next_step`重塑和S1-03的自动结果重塑各由其票负责。

与S1-04可以并行；GUI文件本票最多涉及求解导入smoke，不修改设置或View函数。共享import声明由主Agent/HOST按真实语义协调，不因同文件建立串行依赖。

## 行为、失败与恢复

同一盘面两种Single优先级保持；`.cands`继续快照；root公开类与新入口类identity相同；CLI完整求解继续只有卡住时调用既有回溯。导入错误或目录/引用门禁失败由本票owner在本票范围定位和修复，真实测试通过才提交本票完成证据。
