# S1-01 方案设计总结

## 阶段结果

S1-01 已把已批准的“求解模块目录迁移”方向展开为可独立实施、测试和验收的设计。目标 Module 是 `shudu.logic_solver`，一个公开入口，内部按 engine、project、results、single、evidence、auto、diff 归属共同变化的求解知识；根入口继续承担 CLI/历史导入 Adapter。设计保持 S1-01→S1-02/S1-03 的真实目录、类型和阶段依赖，S1-04 独立。

## 三图闭合摘要

业务流程从根入口或现有调用方进入公开 Module，经过原 solver 顺序和结果构造，回到 Hint/Game/CLI 的既有消费出口；导入错误和门禁失败有本票修复回路，完整 solve 卡住时回到既有回溯。

数据流程由 caller 生产 board/notes，rules 和 Numba core 提供既有真源，Module 产生步骤/候选/日志/错误，原调用方消费，HOST 读取测试与执行面证据；没有新增缓存、IO 或全量投影。

逻辑流程保持构造、位掩码初始化、当前能力执行、结果返回和完整 solve fallback 状态；单步和自动 capability 的新合同分别留给 S1-02/S1-03。
