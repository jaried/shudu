## 1. objective

让“提示”成为独立的推荐 capability：基于当前正式棋盘，按项目支持的全部逻辑算法稳定顺序寻找下一条可解释步骤；自动解决菜单的勾选集合只控制自动执行。

关卡 119 核心验收：

- 默认自动配置未勾选 Hidden Pair 时，提示仍返回 Hidden Pair；
- 自动算法全部关闭时，提示仍返回 Hidden Pair；
- Hidden Pair 为第 6 行的 3/6：R6C2 / R6C7，删除 R6C2 的候选 7。

## 2. 事实与根因

现有调用链：

```text
Game.hint()
  -> make_hint(board, notes, wrong)
  -> pending_step(board, notes)
  -> ShuduSolver.next_step()
  -> already_noted(step, notes)
```

`next_step()` 已使用全部逻辑算法。问题是 `already_noted()` 把可见 `Game.notes` 当作逻辑完成证据，而 `Game.notes` 同时可能来自截图、玩家手工笔记、自动算法候选投影和自动笔记。自动配置触发候选重算后因此能够间接改变推荐结果。

目标态直接删除这条隐式数据通道：recommendation 不读取 notes。

## 3. Module / Interface / Seam / Adapter / 文件布局

### Module：ShuduSolver

**Interface**

`next_step() -> LogicStep | None`

合同：

- 使用全部支持的逻辑算法；
- 固定顺序：Hidden Single → Naked Single → Naked Pair → Hidden Pair → Naked Triple → Pointing Pair → Box-Line Reduction → X-Wing → XY-Wing；
- 返回第一条逻辑步骤；
- 不读取 `UserSettings.auto_techniques`；
- 不读取可见 notes；
- 不进入回溯。

### Module：Hint

**Interface**

`make_hint(board, wrong) -> Hint`

合同：

- wrong cells 优先返回错误提示；
- 正常状态只请求一次 `ShuduSolver.next_step()`；
- `Game.notes` 不参与步骤选择或完成判断；
- `LogicStep -> Hint` 保持现有语义适配；
- 不复制高级算法识别。

**Seam**

`Game.hint()` -> Hint Module -> `ShuduSolver.next_step()`

**Adapter**

`shudu/sudoku_hints.py` 继续承担 `LogicStep -> Hint`；不新增 Adapter 注册表或 Protocol。

## 4. 业务行为

1. 提示只读。
2. wrong cells 优先返回错误提示。
3. 正常盘面由项目 solver 使用全部逻辑算法找第一步。
4. 自动解决只消费用户勾选集合。
5. 自动配置持久化继续只服务自动执行。
6. `Game.notes` 只服务可见候选/玩家交互，不参与 recommendation。
7. 玩家只修改候选笔记、未改变正式数字时，再次提示允许重复同一逻辑步骤。
8. 自动完成真实改变正式棋盘后，后续提示允许随新棋盘改变。
9. 提示不使用完整求解或回溯答案。

## 5. 验收标准

- [ ] 关卡 119 默认自动集合下，下一条提示为 Hidden Pair。
- [ ] 关卡 119 `auto_techniques=set()` 下，下一条提示仍为同一 Hidden Pair。
- [ ] Hidden Pair 未勾选时，推荐仍可使用 Hidden Pair。
- [ ] 同一 board 下任意 notes 内容不改变推荐步骤。
- [ ] recommendation 最多请求一次 `next_step()`。
- [ ] 提示不修改 `board`、`notes`、`history`、错误次数。
- [ ] 自动完成继续严格执行选择集合。
- [ ] 提示不调用 full solve 或 backtracking。
- [ ] GUI/Tk 相关门禁真实执行，环境 skip 不作为通过。
- [ ] README、ADR、codebase-design review 与代码行为一致。
