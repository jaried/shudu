# BUG-D01 方案决策：提示推荐使用全算法且尊重现有候选进度

- 状态：方案已决策，实施已提交，待本地回归验收
- 类型：BUG
- 优先级：P1
- 范围：Hint recommendation / notes progress
- GitHub Issue：不使用；本项目以 docs Issue 为真源

## 1. objective

让提示同时满足两个独立合同：

1. **算法能力**：固定使用全部支持的逻辑算法，不受自动完成勾选影响。
2. **用户进度**：现有候选笔记中已经完成的删除不重复提示。

关卡 119 的目标行为：

- R6C2={3,6,7}、R6C7={3,6} 时，可提示 Hidden Pair 删除 R6C2 的 7。
- R6C2 已变为 {3,6} 时，不再提示删除 7，而是继续寻找后续未完成步骤。
- 两个 Hidden Pair source cell 都必须保持绿色。

## 2. 根因

问题由两个通用机制叠加产生：

1. Hint selector 一度完全忽略 `Game.notes`，因此 solver 从正式棋盘重新得到已经由玩家完成的 elimination。
2. Hint View 对高亮区域强制使用 `LogicStep.candidates`，会把现有 notes 中已经删除的候选重新画出来。

Hidden Pair 还有一个独有视觉覆盖问题：

- R6C2 同时是 source 和 elimination target；
- elimination target 的背景覆盖了 source 的绿色；
- 文案说“绿色两格”，界面只显示一个绿色格。

## 3. Module / Interface / Seam / Adapter

### Module：ShuduSolver

`next_step() -> LogicStep | None`

只负责算法事实，固定使用全部技巧，不读取自动配置或 notes。

### Module：Hint

`make_hint(board, notes, wrong) -> Hint`

- board：算法事实；
- notes：候选删除进度；
- wrong：错误格 gate；
- `Hint.pending_eliminations`：当前仍待完成的候选删除。

### Seam

`Game.hint() -> Hint -> ShuduSolver.next_step()`

已完成 elimination step 由 Hint 在同一个 solver 实例中推进；不修改 Game。

### Adapter

`sudoku_hint_view.py`：

- 优先显示现有 notes；
- 只有当前格没有 notes 时才回退到 solver candidate snapshot；
- 红色删除只来自 `Hint.pending_eliminations`；
- source 背景优先于 elimination-target 背景。

## 4. 受影响范围

共用进度逻辑的 elimination 技巧：

- Naked Pair
- Hidden Pair
- Naked Triple
- Pointing Pair
- Box-Line
- X-Wing
- XY-Wing

Hidden Single / Naked Single 为填数步骤，不属于本类重复删除问题。

## 5. 验收

- [ ] 自动算法未勾 Hidden Pair 时 Hint 仍能使用 Hidden Pair。
- [ ] 已从 notes 删除的候选不重新显示、不重新提示。
- [ ] 部分完成的步骤只标红剩余候选。
- [ ] 已完全完成的 elimination step 会推进到下一逻辑步骤。
- [ ] Hidden Pair 两个 source cell 都为绿色。
- [ ] 七种 elimination 技巧共享同一进度行为。
- [ ] Hint 不修改 board / notes / history。
- [ ] 自动执行仍只消费 `auto_techniques`。
- [ ] 不调用 full solve / backtracking。
