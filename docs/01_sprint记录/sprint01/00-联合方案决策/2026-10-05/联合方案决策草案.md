# 联合方案决策：提示推荐与自动完成配置解耦

- 状态：方案已决策，实施已提交，待本地回归验收
- 日期：2026-10-06
- 仓库：`jaried/shudu`
- 分支：`main`
- 范围：提示推荐、可见候选进度、自动解决算法配置

## 1. 决策结论

1. 提示固定使用项目支持的全部逻辑算法，按稳定优先级寻找当前仍未完成的第一条可解释步骤。
2. 自动完成只执行用户勾选的 `auto_techniques`；该配置不裁剪提示算法集合。
3. 算法是否成立只由正式棋盘与 solver 候选状态决定。
4. `Game.notes` 不作为算法证明或候选真源，只作为“用户已经完成哪些候选删除”的进度投影。
5. elimination step 已全部反映在现有 notes 时，Hint 在同一个 solver 实例中推进该步骤并继续寻找下一步。
6. elimination step 只完成一部分时，Hint 只暴露仍待删除的候选。
7. 提示保持只读，不修改 board、notes、history，不使用完整求解或回溯。
8. Hidden Pair 的 source cell 即使同时是 elimination target，也保持绿色 source 视觉语义。

## 2. 关卡 119 验收事实

正式棋盘：

```text
7183..459
6924..738
453879126
2...3.9..
...6...7.
5......82
.....7.4.
146583297
........3
```

基础算法事实：

- R6C2 = {3,6,7}
- R6C7 = {3,6}
- 第 6 行数字 3、6 只可能位于 R6C2 / R6C7
- Hidden Pair 的算法动作是删除 R6C2 的候选 7

用户进度语义：

- R6C2 仍显示 7：提示可以推荐该 Hidden Pair，并只标红待删的 7。
- R6C2 已只剩 {3,6}：该 elimination 已完成，提示不得再次要求删除 7，应继续寻找后续未完成步骤。
- Hidden Pair 是否在“自动解决算法”中勾选，不影响上述提示行为。

## 3. Module → Interface → Seam → Adapter → 文件布局

### Module：项目逻辑 solver

**Interface**

`ShuduSolver.next_step() -> LogicStep | None`

合同：

- 使用全部逻辑算法的稳定顺序；
- 算法事实只依赖正式棋盘和 solver 内部候选状态；
- 不读取 `UserSettings.auto_techniques`；
- 不读取 GUI；
- 不进入回溯。

### Module：Hint

**Interface**

`make_hint(board, notes, wrong) -> Hint`

合同：

- `board` 决定算法事实；
- `notes` 只投影候选删除进度；
- `wrong` 优先产生错误提示；
- `Hint.pending_eliminations` 只包含当前仍待执行的删除；
- `LogicStep` 仍保留完整算法事实，不被 UI 进度裁剪。

### Seam

```text
Game.hint()
  -> Hint Module
     -> ShuduSolver.next_step()
     -> LogicStep
     -> pending elimination projection
     -> Hint
```

### Adapter

`shudu/sudoku_hints.py` 继续承担 `LogicStep -> Hint` 语义适配。

`shudu/sudoku_hint_view.py` 只消费 `Hint.pending_eliminations` 和 `Hint.sources`：

- 当前 notes 已不存在的候选不重新显示；
- source 与 elimination target 重叠时 source 绿色优先。

### 文件布局

不新增生产 Module，不增加 Strategy / Protocol / 注册表：

```text
shudu/
  sudoku_hints.py
  sudoku_hint_view.py
  sudoku_game.py
tests/
  test_sudoku_hints.py
  test_architecture.py
```

## 4. 受影响算法审查

候选删除类算法共用同一个 Hint 进度 seam，因此统一适用：

1. Naked Pair
2. Hidden Pair
3. Naked Triple
4. Pointing Pair
5. Box-Line
6. X-Wing
7. XY-Wing

其中 Hidden Pair 还有一个独有视觉情况：source cell 本身可能也是 elimination target，因此需要 source 绿色优先级。

Hidden Single / Naked Single 是 placement step，不存在“已经删掉某候选却再次提示删除”的同类问题。

## 5. 执行面

- 自动配置读取面：不进入 Hint。
- notes 读取面：仅检查 step.eliminations 对应候选当前是否仍可见。
- 算法计算面：只在已完成 elimination step 上继续 `next_step()`，直到第一条未完成动作；有上界，不进入 full solve。
- 副作用：0；Hint 仍只读。
- process / remote：0。
