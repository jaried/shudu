状态：approval_draft；Q1 待裁决；批准后新增 Issue。Parent：S1-09。Blocked by：无；不依赖新字体 API，可以使用现有 View 完成运行环境资格。依据：[联合方案](../../../00-联合方案决策/2026-10-12/界面文字联合方案决策草案.md) 第 3、5.3、9 节。

## 问题与独立结果

现有 Ubuntu/GNOME Wayland/XWayland 的 uv Python/Tk 研究较强支持 X core 后端，系统字体安装不能证明 Tk 使用可缩放字体。推荐交付在用户现有 Ubuntu 26.04 x86_64 上可真实运行原应用、通过原数值/OCR/GUI 门禁、且同一 Tk 进程具备 Xft 的独立项目环境。它不依赖字体生产修复或 Windows 显示票。

## Module、接口、布局与范围

环境 owner 为宿主与 uv：系统常规 GIL CPython 3.14 + python3.14-tk / Tk 8.6.17 Xft，系统 Noto Sans CJK SC / DejaVu Sans；应用仍是现有 GUI 入口，uv 管理独立 `.venv-linux`。numpy 2.5.3、numba 0.67.0、llvmlite 0.49.0、opencv-python-headless 4.14.0.94 按 uv.lock 保持；不增加生产依赖或改变求解/OCR 代码。

独立可执行 Seam 为 `scripts/check_tk_runtime.py`：在调用者指定项目解释器的同一进程创建隐藏 Tk，输出一个结构化资格结果并退出；完成后 destroy root。只读版本、windowingsystem、`tk::pkgconfig get fontsystem`、实际 family、固定字符样本的 actual/measure、tk scaling。required Linux fontsystem=xft；不识别此能力或 Tk 错误时退出非零并报告实际失败。其他平台报告 not_applicable，工具不是生产导入的 Module。对应 `tests/test_tk_runtime_check.py` 校验成功/缺 Tk/非 xft/销毁 root/退出码与结果语义；不把测量宽度当成无缺字证明。

owner_surface：README Linux 启动和测试段、独立 CLI 和对应测试、当前宿主环境资格结果及本票报告。允许环境动作限于方案确认的本机发行版包与项目 `.venv-linux`；每次环境替换或批量覆盖先核对实际路径/链接/范围并取得相应授权。应用启动不读字体文件、不扫描库、不启动探测子进程、不安装系统包、不联网。

推荐宿主包对象为 Python 3.14 对应 tkinter、fonts-noto-cjk、fonts-dejavu-core；Worker fresh-read 已安装状态和包候选后只补当前缺失对象。具体 apt 安装属于宿主维护授权范围，当前草案不在 Windows 执行。已有环境内容先展示保全/替换动作，授权后按已核定方案执行；不删除并行工作或自行创建临时 worktree。

同步命令：`UV_PROJECT_ENVIRONMENT=.venv-linux uv sync --locked --python /usr/bin/python3.14 --no-managed-python --no-python-downloads`。原 GUI 启动用 `.venv-linux/bin/python sudoku_gui.py`。README 的已验证版本说明只在实际门禁通过后更新为真实版本与能力；当前 3.12.15 研究记录继续作为历史事实。
