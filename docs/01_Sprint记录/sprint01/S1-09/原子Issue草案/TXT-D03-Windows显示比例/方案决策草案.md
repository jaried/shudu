# TXT-D03：Windows 启动显示比例

状态：approval_draft；Q2 待裁决；批准后新增 Issue。Parent：S1-09。Blocked by：无；可在原 View 上独立验证。依据：[联合方案](../../../00-联合方案决策/2026-10-12/界面文字联合方案决策草案.md) 第 5.4、6、9 节。

## 问题与独立结果

历史 Windows 隐藏 Tk 探针显示 DPI unaware，实际项目进程尚未运行。推荐交付首次 Tk 前明确 system-aware 的原生 Tk 启动能力，以及 100/125/150/200% 显示比例下真实布局/菜单/命中结果；支持同 DPI 显示器移动和原窗口缩放。不同 DPI 动态跨屏属于 Q2 的另一交付范围，未作为推荐分支隐含能力。

## Module、接口、Seam、Adapter 与文件

WindowsDisplay 属 GUI 启动层；目录 `shudu/window_display/`，唯一公开入口 `__init__.py` 导出 prepare 和不可变 DisplayState；internal `_prepare.py` 负责一次执行与结果，`_windows.py` 负责 Win32 ctypes。

`prepare() -> DisplayState` 的字段 status/awareness/diagnostic；status 为 ready、inherited、failed、not_applicable。非 Windows 不读取 Windows API，为 not_applicable。Windows 在 GUI.main 创建首次 Tk 前调用 SetProcessDpiAwarenessContext(SYSTEM_AWARE) 并读回实际上下文。设置成功或既存 system-aware 为 ready；既存其他模式为 inherited；失败为 failed，保留原错误与实际值。同进程重复调用复用首次结果，系统设置最多一次，首次失败不会被缓存伪装成成功。

已设置上下文不重设、不切换线程模式、不背景重试。inherited/failed 输出一次明确启动诊断，原 GUI 启动行为继续；只有实际达到批准上下文的组合通过本票 system-aware AC。窗口大小仍由原配置和 Configure 管理，字体/菜单工作区通过原能力处理，prepare 不调用字体、Game、solver、Store、截图或原生窗口创建。

实际 ctypes 绑定设置 argtypes/restype/use_last_error；保存 API 错误后再读上下文，避免后续调用覆盖错误。Seam 为公开 prepare 的可控 Win32 Adapter及独立新进程“prepare→Tk”启动；错误/已设置路径必须在独立进程验证，不在已创建 Tk 的测试进程全局重设。新依赖为标准库 ctypes，无新 wheel 或平台平台注册。

owner_surface：新 window_display 全目录；GUI.main 首 Tk 前唯一调用和启动诊断；新 `tests/test_window_display.py` 和本票 Windows 宿主测试/结果。GUI.main 之外的 Window 字体提示/_menu/show_settings 归 TXT-D01，函数修改互不重叠所以并行；不得回退其他票编辑。
